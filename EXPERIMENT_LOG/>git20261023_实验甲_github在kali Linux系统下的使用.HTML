模块四 · 本次实操：从链接到拉起的完整流程

本模块记录 2026-10-23 在 Kali 下，将仓库从 root 迁到 lee 用户、 重建 SSH 认证、并成功 git pull 的真实操作链路。

① 迁移目录归属（root → lee）

sudo cp -r /root/security-lab /home/lee/ sudo chown -R lee:lee /home/lee/security-lab
cp -r 会连 .git 一起复制， 所以复制过去本身就是完整可用的仓库，远程地址不丢。
复制不会影响“能否拉取”，但会变成两份独立副本： root 那份 pull 了，lee 这份不会自动同步，反之亦然。

② 确认身份与目录

whoami # 确认为 lee cd ~/security-lab pwd # /home/lee/security-lab
提示符已是 (lee㉿192) 时，不要再执行 su - lee——自己切自己会“身份验证失败”，纯属多余。

③ 首次连接 GitHub：指纹确认

git pull # 提示：Are you sure you want to continue connecting (yes/no/[fingerprint])? yes
这一步必须输完整的 yes，只按 y 回车无效； 此处 Ctrl+X 也不生效，退出请用 Ctrl+C。
确认后会出现 Warning: Permanently added 'github.com' (ED25519) to the list of known hosts. 指纹确认即完成。

④ 排查认证失败：Permission denied (publickey)

ls -la ~/.ssh # 检查 lee 是否有密钥 cat ~/.ssh/id_ed25519.pub # 查看公钥内容
本次 lee 用户下无可用密钥，需重新生成并绑定 GitHub。

⑤ 为 lee 生成 SSH 密钥

ssh-keygen -t ed25519 -C "Nicky@lieenten"
三个提示全部直接回车：保存路径 → 密码 → 确认密码，均留空。
cat ~/.ssh/id_ed25519.pub # ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIMAWUe9dbX0Fye8tp9C+9mY3FV+jd4ZCU1FXPF7zx/Z5 Nicky@lieenten

⑥ 把公钥绑定到 GitHub 账号

步骤操作
1登录 GitHub → 右上角头像 → Settings
2左侧菜单 → SSH and GPG keys
3New SSH key
4Title 填 lee-kali，Key type 选 Authentication Key
5Key 框粘贴整行公钥（含结尾注释）→ Add SSH key

⑦ 测试认证与拉取

ssh -T git@github.com # Hi Hannam1VM! You've successfully authenticated, but GitHub does not provide shell access. cd ~/security-lab git pull # 已经是最新的。
Hi Hannam1VM! 对应的是 GitHub 账号名，不是系统用户名 lee，属正常现象； does not provide shell access 也是正常提示，不算失败。

⑧ 权限检查（SSH 对权限敏感）

ls -l ~/.ssh/id_ed25519* # -rw------- id_ed25519 ← 600，私钥仅本人可读 # -rw-r--r-- id_ed25519.pub ← 644
chmod 600 ~/.ssh/id_ed25519 # 权限不对时修正

⑨ 在浏览器中打开 HTML 文档

firefox ~/security-lab/EXPERIMENT_LOG/*.HTML
若以普通用户打开 /root/… 下的文件，会报 Access to the file was denied——因为 /root 为 700 权限。 迁移到 lee 家目录后即可正常访问。
可用 mv 把中文长文件名改为简短英文， 如 git20261023_kali.html，后续打开更方便。
